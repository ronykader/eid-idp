Civil Registry Connector Spec

Technical integration schema, lifecycle orchestration flows, and reconciliation metrics

Ecosystem Integration Overview

Sint Maarten's Federated eID Ecosystem relies on a secure, bi-directional verification connector with the **Civil Registry database (BSN Archive)**. This integration governs identity enrollment, lifecycle transitions (births and deaths), and write-back synchronization to ensure non-repudiation and prevent key exploits.

1. Verification & UIN Write-Back Flow

When a citizen registers on the portal, their demographics are verified synchronously. If validated, the issued status is written back to the Civil Registry database:

1
Citizen Submits Application
Citizen enters their BSN Number / National ID Number alongside demographics in the Next.js onboarding wizard.
2
Synchronous Civil Registry Lookup
The eID backend queries the civil_registry_records table to check matching dossiers. If the record does not exist or is flagged as Deceased, registration is rejected with 400 Bad Request.
3
UIN Assignment
The eID profile imports the pre-allocated UIN (Unified Identification Number) mapped to the BSN dossier.
4
Write-Back Mapping Update
In the same database transaction, the Civil Registry record's eid_mapping_status column is updated to issued.

🔒 Security Mapping Rule

Writing back the issued status directly to the BSN database prevents the same BSN/National ID dossier from being reused to register another eID profile, eliminating identity duplication vectors.

2. Verification API Reference

Endpoint: POST /api/v1/civil-registry/verify 

curl -X POST http://localhost:8082/api/v1/civil-registry/verify \
  -H "Content-Type: application/json" \
  -d '{
    "bsn_number": "123456"
  }'

JSON Response (Success):

{
  "success": true,
  "message": "Citizen record verified successfully in Civil Registry archive",
  "record": {
    "uin": "UN-SXM-26-000001-9",
    "bsn_number": "123456",
    "national_id_number": "NID-987654",
    "full_name": "John Connor",
    "dob": "1990-05-15",
    "status": "active",
    "eid_mapping_status": "issued"
  },
  "sla_metrics": {
    "latency_ms": 45,
    "compliance": "SLA_METRIC_PASS",
    "target_ms": 100
  }
}

3. Lifecycle Events Flow (Births & Deaths)

Updates from the national registrars automatically sync citizen credentials to prevent posthumous exploits:

A
Death Notification Triggered
Registrar dispatches a DEATH_NOTIFICATION event containing the deceased's pre-assigned UIN.
B
Civil Registry Suspension
The BSN dossier status changes to deceased and its mapping status changes to revoked.
C
Credentials Revocation Loop
The eID account status switches to suspended, and all registered credentials (passwords, TOTPs, WebAuthn keys) are set to revoked in the database, blocking all SSO access immediately.

4. Lifecycle Event API Reference

Death Notification Endpoint: POST /api/v1/civil-registry/lifecycle-event 

curl -X POST http://localhost:8082/api/v1/civil-registry/lifecycle-event \
  -H "Content-Type: application/json" \
  -d '{
    "event_type": "DEATH_NOTIFICATION",
    "uin": "UN-SXM-26-888888-2"
  }'

JSON Response (Success):

{
  "success": true,
  "message": "DEATH_NOTIFICATION processed. eID citizen profile and credentials associated with UIN UN-SXM-26-888888-2 have been suspended and revoked."
}

Birth Pre-Provisioning Endpoint: POST /api/v1/civil-registry/lifecycle-event 

curl -X POST http://localhost:8082/api/v1/civil-registry/lifecycle-event \
  -H "Content-Type: application/json" \
  -d '{
    "event_type": "BIRTH_PRE_PROVISION",
    "uin": "UN-SXM-26-777777-3",
    "bsn_number": "777777",
    "national_id_number": "NID-777777",
    "full_name": "Sarah Connor Jr",
    "dob": "2026-07-20"
  }'

JSON Response (Success):

{
  "success": true,
  "message": "BIRTH_PRE_PROVISION processed. Profile pre-provisioned in Civil Registry under UIN UN-SXM-26-777777-3."
}
