1. Citizen Registry & Dossier Management

Administrators review citizen profile details, confirm document uploads, and update registry statuses on the **Citizens** management page (`/admin/citizens`).

Action A
Reviewing Pending Registrations

Browse the citizen registry table. Click **View Details** on any pending row to inspect the submitted name, CRIB number, and address. Review uploaded photo and ID scans in the overlay modal.

Action B
Manual eID Issuance

If the system setting is set to manual mode, citizens must be manually approved. Click **Generate eID** to issue a unique national eID serial key and activate the citizen profile.

Action C
Status Changes (Suspensions)

Use the details modal to update the citizen status:

  • Active: Permits federated SSO logins across government portals.
  • Suspended: Rejects all authentication requests, blocking access.

2. Credentials Registry & Client Registrations

Control active cryptographic authenticators and manage federated Relying Party client parameters:

🔑 Biometric Keys Administration (`/admin/credentials`)

Browse the global directory of registered FIDO2 / WebAuthn credentials bound to citizen accounts.

  • Key Audit: Verify the credential ID, key signature algorithms, and the active status of registered hardware tokens.
  • Emergency Revocation: Administrators can manually delete an authenticator key if a citizen reports their biometric device as compromised or lost.
🔌 OAuth Client Applications (`/admin/clients`)

Manage the configurations for federated platforms linked to the eID identity provider:

  • Client ID / Secrets: Add or edit Relying Party portals (e.g., `mygov-broker`, `tax-portal`).
  • Redirect URI White-listing: White-list exact redirect endpoints to prevent Open Redirector hijack attempts.

3. Global System Configuration

Configure eID platform generation rules and configuration bindings on the **System Settings** page (`/admin/settings`).

Setting 01
eID Generation Mode

Toggles how the registry processes new applications:

  • Automatic Mode: Automatically generates and assigns eID serial keys upon citizen registration. Suitable for low-risk testing or fully integrated database states.
  • Manual Mode: Newly registered citizens are saved as pending. Requires an administrator or PSC operator to manually review documents and click "Generate eID" to issue credentials.
Setting 02
MFA Gateway Configuration Bindings

Verify and administer settings for SMS Gateway (BulkSMSBD) delivery systems configured inside the `.NET` web services config registry:

  • SMS_API_KEY / SMS_SENDER_ID: Verify keys are securely configured under the application server profile configurations to prevent dispatch failures.

4. Security Logs & Compliance Auditing

Audit identity release transactions and verify security trail compliance on the **Auth Logs** page (`/admin/logs`).

Annex E Evidence Trail Inspections

Review the real-time paginated table of transaction logs populated directly from the `audit_evidence_records` database table. Ensure that:

  • Each record carries a unique **Reference ID** and **Correlation ID** linked to WSO2.
  • The **Verification Status** reads `VERIFIED_HIGH_ASSURANCE` for WebAuthn passkey handshakes.
  • The **Payload Hash** displays the SHA-256 cryptographic digest of the released claims, proving that no plaintext PII is written to the audit log.

🚨 NIST & eIDAS Security Standards

Under NIST SP 800-63B and eIDAS High Assurance guidelines, audit logs are read-only and immutable. Deletion or modification of rows in the `audit_evidence_records` registry table is strictly prohibited and audited by the National Security Agency.
