Chapter 01

The Federation Trust Loop

Sint Maarten's national identity ecosystem binds WSO2 Identity Server (Broker) and the eID Platform (OpenID Connect Provider) through a bidirectional security trust loop:

  • Outbound Challenge: When a user logs in, WSO2 delegates the request to the eID platform via a signed OpenID Connect authorization code flow.
  • Biometric Assertions: The eID platform performs secure FIDO2 biometric checks and issues signed JWT identity tokens.
  • Inbound Callback: WSO2 IS accepts, validates, decrypts, and maps these tokens, initiating local SSO session controls.
Chapter 02

Step 1: Register WSO2 inside eID

Before WSO2 IS can request user credentials from the national eID core, it must be whitelisted in the eID Administration dashboard:

1

Create Trusted OAuth Client

Log in to the eID Control Panel, go to SSO Clients, and click Create Client.

2

Configure Client Identifiers

Set the parameters exactly as follows:

  • Client ID: eid-wso2-broker-client-id
  • Client Secret: eid-wso2-broker-client-secret-key-2026
3

Configure Central Inbound Redirection URI

Set the callback URL of WSO2 IS to handle authorization checks:

Redirect URI: https://localhost:9443/commonauth

4

Define Allowed Scopes

Check the required attribute releases: openid, profile, email, uin, bsn_number, and municipality. Save the client application profile.

Chapter 03

Step 2: Register eID inside WSO2

Next, WSO2 must be configured to trust incoming assertions from the Sint Maarten eID Platform as a federated Identity Provider (IdP):

1

Create Identity Provider

Open WSO2 Carbon Management Console. In the left panel, navigate to Identity Providers -> click Add. Define the name as eID-Provider.

2

Configure OAuth2/OpenID Connect Federated Authenticator

Expand Federated Authenticators -> OAuth2/OpenID Connect Configuration. Check the Enable OAuth2/OpenID Connect and Default checkboxes.

3

Configure Identity Provider Endpoint URLs

Set the parameters exactly as follows:

  • Client ID: eid-wso2-broker-client-id
  • Client Secret: eid-wso2-broker-client-secret-key-2026
  • Authorization Endpoint: http://localhost:8082/api/v1/oauth/authorize
  • Token Endpoint: http://host.docker.internal:8082/api/v1/oauth/token *(Use docker proxy route if containerized)*
  • UserInfo Endpoint: http://host.docker.internal:8082/api/v1/oauth/userinfo
  • Additional Query Parameters: scope=openid profile email uin bsn_number municipality
Chapter 04

Chapter 4: Dialect Attribute Mapping

WSO2 IS must map incoming claims from Sint Maarten eID to local WSO2 claim dialects. Under your eID-Provider settings, expand **Claim Configuration** -> **Basic Claim Configuration**:

  • Select the Define Custom Claim Dialect option.
  • Click the Add Claim Mapping button to establish these bindings:
eID Claim (Identity Assertion) WSO2 Dialect Claim Target
given_name http://wso2.org/claims/givenname
family_name http://wso2.org/claims/lastname
email http://wso2.org/claims/emailaddress
uin http://wso2.org/claims/nationalid
bsn_number http://wso2.org/claims/electronicid

Ensure that the **User ID Claim URI** dropdown is set to http://wso2.org/claims/emailaddress so that WSO2 establishes user session mapping using the verified email address.

Chapter 05

Just-In-Time (JIT) Provisioning

To prevent identity registrars from having to pre-create shadow accounts inside WSO2's local user directory (LDAP/JDBC User Store), configure silent **Just-In-Time (JIT) Provisioning**:

  • Open the **eID-Provider** configuration page.
  • Expand the **Just-in-Time Provisioning** section.
  • Select the **Provision Silently** radio button.
  • Set the **Provisioning User Store Domain** to `PRIMARY`.
  • Click **Register** or **Update** at the bottom of the page.
Result

Upon successful biometric login in eID, WSO2 IS automatically intercepts the mapped attributes, creates a matching local user entry silently behind the scenes, and issues local authentication cookies to the browser.
