Chapter 01

Federated SSO Architecture

The Sint Maarten National eID Platform operates as an OIDC Identity Provider (IdP) federated with a central **WSO2 Identity Server** instance. In this topology:

  • Client Application (Relying Party): Applications like MyGov or UpSheba connect directly to WSO2 IS as their primary OAuth identity server.
  • WSO2 IS (Broker/Hub): WSO2 IS intercepts authentication challenges and delegates credential assertions to the national eID backend.
  • eID platform: Hosts passwordless biometrics (FIDO2) and multi-factor validation, generating secure OIDC assertions.
Why use WSO2 as a Broker?

This design allows client applications to use standard OpenID Connect parameters while enabling the government to swap, update, or federate additional identity providers behind the scenes without changing a single line of portal codebase.

Chapter 02

Register Service Provider (SP)

To integrate a new portal like MyGov with the identity cluster, you must first register it as a **Service Provider (SP)** inside the WSO2 Carbon Management Console:

1

Create Service Provider Profile

Navigate to Identity -> Service Providers -> click Add. Define your Service Provider Name (e.g. mygov) and click Register.

2

Configure OAuth2/OpenID Connect Inbound Auth

Expand Inbound Connection Configuration -> OAuth/OpenID Connect Configuration -> click Configure.

3

Input Callback Configurations

Set the Callback URL using regex matches: regexp=http://mygov.test/auth/wso2/callback. Ensure Implicit Grant is unchecked, and ensure Mandatory PKCE is checkmarked to secure token bindings.

4

Extract Application Client Keys

Click Register/Update. Re-open the configuration section and copy the auto-generated OAuth Client Key (Client ID) and OAuth Client Secret.

Chapter 03

Claim Dialects & User Identity

Relying Parties require core identity details of the authenticated citizen. WSO2 maps custom incoming eID claim assertions to local WSO2 dialect claims:

eID Claim (OIDC Assertion) WSO2 Dialect Target Claim Description
sub http://wso2.org/claims/userid Unique federated citizen UUID
email http://wso2.org/claims/emailaddress Verified primary email address
given_name http://wso2.org/claims/givenname First name of the citizen
family_name http://wso2.org/claims/lastname Last name of the citizen
uin http://wso2.org/claims/nationalid Unique National Identification Number
bsn_number http://wso2.org/claims/electronicid Tax / CRIB identifier scope

Configuring claims in Carbon console: Under your Service Provider profile, expand **Claim Configuration**, select **Define Custom Claim Dialect**, add mappings according to the table above, and set the **Subject Claim URI** dropdown to `http://wso2.org/claims/emailaddress`.

Chapter 04

Configure Outbound Authentication

By default, WSO2 attempts to authenticate users against its local LDAP user store. To intercept credential requests and forward them to the secure Sint Maarten eID portal:

  • Open the **Service Provider Details** dashboard.
  • Expand the **Local & Outbound Authentication Configuration** section.
  • Find the **Authentication Type** options.
  • Select the **Federated Authentication** radio button.
  • Choose **`eID-Provider`** from the dropdown menu.
  • Check the **Assert Identity using Subject Identifier** box to preserve federated email values.
  • Click **Update** to save the SP.
Chapter 05

Relying Party Integration Code

Once WSO2 is configured, update your local application credentials. Here is the standard Laravel `.env` profile used to start challenges:

Laravel Environment Config (.env) 
# WSO2 Hub Credentials
WSO2_BASE_URL=https://localhost:9443
WSO2_CLIENT_ID=your-wso2-service-provider-client-key
WSO2_CLIENT_SECRET=your-wso2-service-provider-client-secret
WSO2_REDIRECT_URI=http://mygov.test/auth/wso2/callback
