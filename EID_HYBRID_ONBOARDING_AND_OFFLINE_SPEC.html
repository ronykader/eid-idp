What is Offline Verification & Why is it Needed?

1. The Problem: Connectivity Vulnerability

Sint Maarten's infrastructure is vulnerable to hurricanes and network outages. During power loss or fiber line cutoffs, standard OIDC online authentication fails.

However, critical border controls (such as crossings between the Dutch and French sides) and emergency health check points must verify identities under all circumstances.

2. The Solution: Signed QR Credentials

Offline Verification allows citizens to display a high-assurance **Cryptographic QR Code** from their eID mobile app.

The QR code does not contain plain text databases; instead, it holds a JWT payload signed with the eID registry's **asymmetric private key**. Verifying devices scan the code and validate the signature offline using the pre-cached public key.

Key Capabilities Mapped

  • Asymmetric Trust: Validates signatures without connection to the central database server.
  • Outage-Only Fallback: Automatically triggers when verifier systems detect loss of backend gateway links.
  • Tamper Proof: Any manual claim adjustments break the cryptographic hash, invalidating the signature.
  • Reconciliation Queue: Checked logs are stored locally on scanning devices and synced to the core server once connection returns.

// C# Controller generating signed offline QR assertions
[HttpGet("citizens/offline-qr")]
public async Task<IActionResult> GetOfflineQR()
{
    // 1. Resolve and validate the OIDC session token from request
    var principal = _tokenService.ValidateToken(jwtToken);
    
    // 2. Query citizen demographics from MySQL Registry
    var citizen = await _dbContext.Citizens.FirstOrDefaultAsync(c => c.Uuid == uuid);
    
    // 3. Generate RS256-signed JWT containing core claims
    var qrToken = _tokenService.GenerateToken(citizen.Uuid, citizen.Uin, citizen.Eid, citizen.Email, citizen.Role);
    
    return Ok(new { qr_payload = qrToken });
}

PSC Assisted Enrollment & Camera Integration

1. Why We Need the Biometric Enroller

Under the **EU eIDAS Regulation (Assurance Level High)** and Sint Maarten legal frameworks, binding a digital credential (like a FIDO2 passkey) to a verified physical identity is mandatory. The Biometric Enroller prevents **impersonation and enrollment fraud** by ensuring that the person registering the eID is indeed the legitimate owner of the identity document.

Additionally, it provides an official **assisted channel** for citizens who do not own modern smartphones with biometric scanners, ensuring equal access to digital government services.

2. How It Works (Biometric Processing Logic)

A. Image Acquisition: The operator activates the enroller camera. The browser opens a media stream with a centered oval guide to ensure optimal positioning and light balancing.

B. Landmark Extraction & Hashing: Once captured, the system maps **68 key facial landmarks** (eye spacing, nose bridge shape, jawline angle). These landmarks are converted into a 128-dimensional floating-point **Feature Vector (Face Template)**.

C. Matching & Hashing: The computed vector is compared against the passport photograph using a **Cosine Similarity** algorithm. If the match confidence score exceeds **95.0%**, the template is cryptographically hashed and bound to the citizen record inside the eID registry database.

3. Key Use Cases

  • Assisted Office Enrollment: Validating offline or elderly citizens at counter desks.
  • Verification Override: Resolving identity suspensions if automatic remote document uploads fail matching thresholds.
  • Identity Duplication Checks: Scanning the database to prevent a single citizen from registering multiple active UIN profiles.

ePassport NFC Chip & MRZ Scanner Mappings

1. What is an ePassport?

An ePassport is a secure biometric travel document containing a microchip. The microchip stores demographic claims, biometric data (face image), and public keys signed by the issuing country’s CSCA (Country Signing Certification Authority).

2. Contactless NFC & MRZ Logic

To extract chip data, scanners read the **Machine Readable Zone (MRZ)** (two lines of text at the bottom of the passport page).

The scanner uses details from the MRZ (Passport number, DOB, and Expiry date) to calculate a cryptographic access key. Using this key, the reader establishes a **Basic Access Control (BAC)** connection via NFC to decrypt the chip payload.

3. Pattern B Fallback

If the passport lacks a chip, or the chip is damaged/corrupted, the scanner activates the **Pattern B Documentary Fallback** protocol.

Under Pattern B, the operator manually reviews the security features under UV light and enters passport data manually, maintaining legal onboarding audits despite hardware failures.

Contactless Handshake Logic

// Cryptographic handshake to establish contactless session keys
public class ePassportNfcSession
{
    public byte[] CalculateBACSessionKey(string mrzLine)
    {
        // 1. Extract PassportNumber, DateOfBirth, and ExpiryDate from MRZ
        var input = PassportNumber + DateOfBirth + ExpiryDate;
        
        // 2. Compute SHA-1 hash to generate document access keys
        using (SHA1 sha1 = SHA1.Create()) {
            return sha1.ComputeHash(Encoding.ASCII.GetBytes(input));
        }
    }
}
